# Evaluation protocol

This protocol describes what the saved PacketLens results measure and what they do not establish. The JSON files in
[`../results/`](../results/) are the source of the generated tables in [`RESULTS.md`](RESULTS.md).

## Tasks and data boundaries

PacketLens evaluates two separate tasks:

1. The packet pipeline parses supported packet captures, applies packet-level detectors and policy, and reports
   generated alerts. Synthetic evaluation labels are generated alongside synthetic packets.
2. The offline flow experiments evaluate one-minute volume detectors and per-flow classifiers on CIC-IDS2017 flow
   tables. They do not consume packets and are not part of the live packet pipeline.

The flow experiments use CIC-IDS2017 labels and the CSV files named in each result's `meta.dataset_files` field.
Dataset files are not included in the repository. Each available file is identified by its name, size, and SHA-256
digest in the saved metadata.

## Splits

The per-flow experiment sorts rows by corrected timestamp and uses the first 60% for training and the last 40% for
testing. No random train/test split is used. Feature selection, imputation, and scaling are fitted on training rows;
the main Random Forest threshold is not selected using test labels. The stratified dummy classifier is a seeded
baseline, not a random split.

For volume detectors, the first 60% of the clean Monday series is the training baseline. The rest of Monday is a
clean hold-out used to report false alarms per hour. Friday attack files are evaluated as separate attack series.
Attack-bin labels require at least five labelled attack flows in a minute.

A held-out-machine split is a secondary robustness check, not the primary estimate. Bot source-IP groups are
selected for the held-out portion, and the cleaner diagnostic also removes held-out addresses from both address
columns in training. Source and destination addresses are not model features. Group-level splits remain subject to
the dataset's labeling and traffic-generation structure.

## False-alarm budget

False alarms are measured on the clean Monday hold-out, separately from attack detection metrics. The optional
Granite forecaster calibrates its residual threshold on rolling residuals from Monday training bins only, targeting
one false alarm per hour. Its first 90 attack bins lack the required forecast context and are left unscored. Other
threshold-budget diagnostics use training-only validation data; they do not tune on test labels.

## Duplicate and leakage checks

Per-flow checks compare each preprocessed test feature vector with the training feature vectors, separately by
class. The report records test counts, exact-duplicate counts and rates, plus Random Forest precision and recall on
the test rows with no exact training match. This detects identical feature vectors, not every possible form of
dependence or leakage.

Bot diagnostics additionally compare label-window and attacker-address evidence and report source/machine split
results. These checks are diagnostic: a cleaner split can reduce a particular leakage concern without proving
generalization or validating the source labels.

## Label-window audit

The Bot audit compares flow timestamps and labels with the CIC-IDS2017 documented Botnet (ARES) window. It reports
Bot counts inside and outside that window, traffic involving attacker addresses after the window, and Random Forest
recall inside versus outside the documented window. Post-window labels are not independently validated by this
audit. A discrepancy is evidence of a labeling ambiguity, not proof that the labels are wrong.

## Bootstrap intervals

Precision, recall, F1, and false alarms per hour receive 95% percentile intervals from a deterministic circular
block bootstrap. The per-minute flow-series experiment resamples contiguous blocks of five one-minute bins with
1,000 resamples. The main Random Forest flowmodel row resamples one-minute test blocks with 500 resamples; all
test rows within a minute stay together. The default bootstrap seed is 42.

Intervals are omitted when there are fewer than 30 bins, and the result includes the note `too few to trust`.
Empty samples return no estimate and an explanatory note. A fixed seed makes resampling repeatable; it does not
remove dataset or measurement uncertainty.

## Evidence versus indicative results

* Synthetic evaluation is reproducible evidence that the tested packet detectors respond to the generated cases.
  Because the traffic and labels are generated by the same project, it is optimistic and is not field-performance
  evidence.
* CIC-IDS2017 scores are evidence about the exact files, label definitions, features, split, and implementation
  recorded in the JSON. They are indicative only for other networks, attack instances, and time periods.
* Near-perfect per-flow scores must be read with the duplicate rates and duplicate-free scores beside them.
  The Bot scores must also be read with the label-window audit.
* Throughput is a measurement of one run and varies with the host, Python build, and system load.

Commands:

```text
python -m packetlens reproduce --skip-real
python -m packetlens reproduce
python -m packetlens reproduce --write
python -m packetlens render-results
```

Reproduction is a dry run unless `--write` is specified. Missing dataset inputs are reported as skipped, never
replaced with fabricated results.
